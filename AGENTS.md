# Repository instructions

- Read this file before changing the repository. Preserve the original `Spielbeschreibung`.
- Keep generator functions in `src/core` pure and deterministic. Do not use current time, `Math.random`, DOM or GPU state there. Use independent seeded domains for distinct generated properties.
- Maintain the flat-top main hexagon, exact ground clipping and a roughly pentagonal, optionally displaced center. Each center side has one centered portal owned by one game field or none; its corner zones stay landscape. Generated outer-side entrance footprints come from the untouched raster and stay identical across seeds at the same grid settings. Manual shape edits may change their interior cells while preserving the complete fixed mouth, exactly one owner and no second field touching that side. Freeze the visible layout before manual shape edits so other fields retain their IDs, shapes and metadata. The automatic layout targets connected normal fields with at least 1/16 square world units of visible ground area. Manual editing and placement may retain undersized or disconnected fields and paths: use the configurable rules to warn, and block only exports when the selected policy requires it. Structural clipping and ownership constraints remain enforced. Flat fields use their lowest original cell elevation plus an explicit height offset; terraced fields may retain their cell elevations plus that offset. The requested total field count includes the pentagon; report impossible layouts explicitly. Test geometric and graph changes with invariants.
- Validate imported configuration and API inputs with the versioned strict schema. Explicitly migrate or bump versions when changing reproducible output semantics.
- Keep React editor, Three.js rendering and local filesystem persistence separate. Custom assets must normalize occupied bounds and keep stable content IDs.
- Terrain and game-field caps must stay horizontal; every height difference has a vertical wall, including connected fields and pentagon portals. Do not add interpolation ramps or omit walls at game-field connections. Test these mesh invariants.
- An enabled tile border occupies an exact inward strip of the main hexagon, interrupted by actual path surfaces that reach the outer edge. Keep complete normalized object footprints out of the border zone, including transparent mode; conflicting saved placements remain in configuration and are only hidden from generated output. Disabling the border restores them. Preserve legacy output through a disabled border when migrating older projects.
- Center edits preserve existing field identities, metadata, mouths and all unaffected raster areas by default. Adapt only directly affected fragments and whole center portals; rebuild paths and placements only when the explicit editor preference enables it. Reject a completely displaced field or fixed entrance collision instead of silently replacing fields.
- Explicit action rolls use independent seeded draws by field ID and persisted roll revision with configurable nonnegative weights. Roll all visible fields including the center in one undo step; do not change geometry, heights, colors, labels, objects or existing initial-generation recipes when merely changing weights.
- Keep generated files in ignored `working/`. Do not commit exports, secrets, caches, build results or dependencies.
- Run `npm run check` and the relevant browser tests after implementation changes. Fix failures before handing off. Do not lower quality thresholds to hide failures.
- Document material behavior changes, schema decisions and known limits in the repository docs.
- Use subagents for independent substantial tasks when explicitly requested by the user; coordinate shared types before parallel edits.
